# 食品棚卸月次処理システム

飲食チェーン店舗の**月次の食品棚卸**を自動化するツールです。
本部から届く4つのファイルを取り込むと、前月比較つきの完成Excelができあがります。

すべての処理はブラウザの中で完結します。**原価データが店舗PCの外へ出ることはありません。**

---

## 解決したい課題

棚卸は毎月、店舗の担当者が手作業で行っていました。

| 作業 | 起きていたこと |
|---|---|
| 前月の期末在庫を当月の期首在庫へ転記する（数百行） | 行がずれても誰も気づけない。実際に**80行以上ずれた月があった** |
| 発注実績を数えて期中仕入に入れる | 発注の単位（箱・袋）と棚卸の単位が違い、換算を手計算していた |
| 自店で買った食材を足す | 対象品目の把握が属人化していた |
| 数字の妥当性を確かめる | 原価率が動いても、原因が入力ミスなのか実態なのか分からない |

**いちばん困るのは、間違いが静かに通ってしまうこと**でした。
数字は埋まっているので一見正しく見え、月次の原価率が数pt動いてから気づきます。

## このシステムがすること

1. **突合は商品コードの完全一致だけ** — 行番号や商品名では照合しません。先頭ゼロも保持します
2. **判断できない入力は、推測せず止めます** — 換算係数が不明なら0で埋めず、出力自体をブロックします
3. **気づくべきことを1件1メッセージで伝えます** — 同じ事象が何十件あっても画面には1行、内訳は折りたたみ
4. **元の帳票を壊しません** — 本部支給のExcelをテンプレートに、入力セルだけを書き戻します。数式・書式・印刷範囲はそのまま

## 月次の流れ

```
STEP 1  4つのファイルを指定        本部マスタ / 前月棚卸表 / 発注累計照会 / 単位計算マスタ
STEP 2  取込結果と指摘を確認        列の対応、エラー・警告・情報
STEP 3  商品の増減を確認            新規・削除・商品名変更・分類変更
STEP 4  自店購入を入力              発注累計に現れない品目
STEP 5  前月比較を見て出力          異常判定 → 完成Excelをダウンロード
```

処理履歴は店舗PC上の SQLite ファイル（`inventory.db`）に残ります。
バックアップはファイルをコピーするだけで完了します。

## 設計の前提

| 前提 | 理由 |
|---|---|
| **サーバを持たない** | 原価データを外部へ送らない。店舗PCに実行環境を用意する必要もない |
| **既存の帳票様式を変えない** | 本部へ提出する書式であり、店舗の裁量では変えられない |
| **誤った帳票は出さない** | 未解決のエラーが1件でもあればダウンロードを禁止します |
| **月ごとのスナップショット** | 後日マスタの分類が変わっても、過去の集計結果は変わりません |

### 技術構成

| 層 | 採用 | 選定理由 |
|---|---|---|
| 言語 | TypeScript（strict） | 商品コードを branded type で守り、数値型での取り違えを型で防ぐ |
| 画面 | React 18 + Vite 5 | — |
| 数値 | IEEE754 倍精度（`number`） | Excel と同じ表現。十進固定小数だとかえって帳票と乖離する |
| xlsx | JSZip ＋ XML直接パッチ | 数式・書式・印刷範囲をバイト単位で保つため、ブックを再生成しない |
| DB | sql.js（SQLite WASM） | 本物のSQLiteファイル。コピーでバックアップでき、他ツールでも開ける |
| ファイル接続 | File System Access API | 一度選べば以後は直接読み書き。非対応環境はダウンロード方式にフォールバック |
| テスト | Vitest ＋ happy-dom | 画面も含めて `npm test` 一発。CIでそのまま回せる |

### レイヤ構成

```
src/
├── ui/        画面（React）
├── app/       取込→計算→比較の順序
├── domain/    ★ 外部I/Oを持たない純粋な計算
├── ingest/    取込・列マッピング・ファイル同一性
├── xlsx/      ZIP+XML 直接パッチ
├── export/    完成Excelの書き戻し
└── storage/   SQLite・ファイル接続
```

依存は上から下へ一方向で、**ドメイン層は何にも依存しません**。
計算・引継ぎ・換算・異常判定はファイルもブラウザも無しで動くため、単体テストが高速に回ります。

### リポジトリに含めないもの

店舗の実データと業務文書は公開しません。

| 対象 | 理由 |
|---|---|
| `*.xlsx` / `*.csv` / `*.db` | 実際の原価・在庫データを含むため |
| `docs/` | 設計書・運用マニュアル等の社内文書。実業績値や業務の詳細を含むため |
| `tests/fixtures/real/expected.json` | 実ファイル検証の期待値（売上高・原価率など） |

実ファイル検証は、対象ファイルと期待値が手元にある場合だけ実行し、無ければスキップします。
期待値の構造は `tests/fixtures/real/expected.example.json`（値はダミー）を参照してください。

画面の動作確認には `npm run testdata` で生成する合成データを使います。実データは使いません。
